## 1. Visual Identity

### 한 줄 규칙

> **복셀 병사들의 장난감 전쟁 — 멀리서 보면 디오라마, 가까이 보면 살아 움직이는 미니어처다.**

### 스타일 정의: Low-poly Voxel 3D + Tilt-shift

DDworld의 비주얼은 두 가지 기법의 조합이다:

1. **Low-poly Voxel 3D**: 캐릭터는 MagicaVoxel로 부위별 분리 모델링하고, Blender에서 본 리깅+애니메이션. 환경은 Low-poly 메쉬. 단색 머티리얼 + Vertex Color 위주, 텍스처 거의 사용 안 함.
   - 레퍼런스: **Bad North** (자동 전투 + 미니어처), **Tabletop Tavern** (인디 검증), **A Short Hike** (따뜻한 톤), **Crossy Road/Cube World** (Voxel 캐릭터)

2. **Tilt-shift (토이렌즈)**: 카메라가 멀어질수록 Depth of Field가 강해지며, 전장이 미니어처/장난감처럼 보인다. 가까이 가면 DOF가 얕아지며 전장 안에 들어온 듯한 몰입감을 준다.

### Voxel 세계 원칙

**모든 요소가 같은 Low-poly 미감을 공유해야 한다.**
캐릭터가 Voxel인데 환경이 매끄러운 HD 메쉬면 따로 논다.

- 캐릭터: MagicaVoxel 큐브 단위 (Head/Body/Arms/Legs/Weapon 분리)
- 환경: Low-poly 메쉬 (각진 형태, 평면 색)
- 단색 머티리얼 + Vertex Color로 색칠 (텍스처 거의 X, GPU Instancing 효율 ↑)
- 그 위에 URP 조명/DOF/Bloom/Tilt-shift가 얹혀서 디오라마 느낌

### 기본 구성

```
[레이어 구조]

3D 환경 (바닥/지형/소품)    ← Low-poly 메쉬 + 단색/Vertex Color
  ↑
3D 캐릭터 (병사/유닛)        ← MagicaVoxel 모델 + Blender 본 애니메이션 (B 방식)
  ↑
UI 오버레이 (카드/정보)     ← UI Toolkit 또는 월드 스페이스 UI
  ↑
포스트 프로세싱              ← Bloom, DOF (Gaussian), Tilt-shift, Color Grading
```

### 캐릭터 모델 가이드라인 (MagicaVoxel)

- **부위별 분리**: Head / Body / Arm_L / Arm_R / Leg_L / Leg_R / Weapon / Shield (그리고 헬멧 등 별도)
- **그리드 크기**: 부위 당 4~10 voxel (8~16 voxel 캐릭터)
- 병종 특성에 따라 부위 비율/색이 다름 — 멀리서도 실루엣으로 구분 가능해야 함
- 단색 또는 2~3색 팔레트 (따뜻한 톤 기준)

| 병종 | 특징 | 핵심 식별 요소 |
|------|------|------------|
| 기병 (Cavalry) | 말 + 기수 (분리 모델) | 큰 실루엣, 말 |
| 창병 (Spearman) | 긴 창 + 방패 | 긴 무기 + 방패 색 |
| 궁병 (Archer) | 활 + 화살통 | 활 들고 있는 자세 |
| 민병대 (Militia) | 단순 농기구/막대 | 작고 다수, 단순 형태 |
| 함정 (Trap) | 사람 X (정적 오브제) | 바닥 오브젝트 |

> 정확한 voxel 수는 모델링하면서 확정. 위 수치는 가이드라인.

### 캐릭터 애니메이션 원칙: Rigid Voxel Animation

**메쉬 변형 없음. 부위는 딱딱하게 움직이고, 생동감은 타이밍과 Scale로 만든다.**

복셀 캐릭터는 일반 3D 캐릭터처럼 메쉬가 부드럽게 휘어지면 안 된다. 팔이 굽혀질 때 메쉬가 벤딩되는 순간 "사실은 부드러운 메쉬에 복셀 텍스처를 입힌 것"으로 인지되어 복셀 고유의 매력이 깨진다. **인형/장난감이 움직이는 느낌**이 핵심이다.

레퍼런스: **Lego 게임 시리즈, Crossy Road, Bad North** — 모두 같은 원칙을 따른다.

**리깅 규칙:**
- MagicaVoxel에서 부위별로 분리 export (Head / Body / Arm_L / Arm_R / Leg_L / Leg_R / Weapon / Shield)
- Blender에서 각 부위 메쉬는 본 1개에 **Vertex Group 100% 바인딩** (또는 Bone Parent)
- 스키닝 웨이트 페인팅 불필요 — 본이 회전하면 메쉬는 변형 없이 그대로 회전만 한다
- 관절 부위(어깨/팔꿈치/무릎)에 살짝 빈 공간이 생기는 것은 의도된 결과 — 장난감/인형 같은 매력을 강화한다

**생동감을 만드는 4가지 기법 (메쉬 변형 없이):**

1. **Squash & Stretch (부위 전체 Scale)**
   - 메쉬는 변형하지 않고, 부위 전체를 Scale로 짝짝 늘이고 줄인다
   - 점프 시작 — Leg 부위 Scale Y 0.7 (스쿼시)
   - 점프 정점 — Body 부위 Scale Y 1.15 (스트레치)
   - Crossy Road의 점프 모션이 이 원리

2. **Anticipation & Overshoot (예비/관성 동작)**
   - 동작 시작 전 살짝 반대 방향으로 (휘두르기 전 살짝 뒤로)
   - 동작 끝나고 살짝 튕김 (정지 위치를 지나쳤다가 돌아옴)
   - 이게 없으면 로봇처럼 보임

3. **Secondary Motion (펜듈럼)**
   - 무기, 망토, 머리 장식 등은 주요 동작보다 1~3프레임 늦게 따라온다
   - 별도 본을 두고 부모 본의 움직임을 따라가되 약간의 지연/관성 적용

4. **과장된 타이밍 (Snappy timing)**
   - 부드러운 보간 곡선 대신 Ease-In/Out을 강하게
   - 동작과 동작 사이의 정지(hold)를 명확하게 — 중간 자세에서 멈춤이 있어야 "딱딱한 귀여움"이 산다

**금지:**
- 메쉬 벤딩 / 스키닝 웨이트 그라데이션 (관절이 휘어지는 효과)
- IK로 자연스러운 보행 모션 — 두 발이 동시에 깡총 뛰는 게 더 어울림
- 부드러운 페이스 블렌딩 (얼굴은 텍스처 교체 또는 부위 교체 방식)

**구현 노트:**
- Blender → Unity export 시 본/메쉬 계층 유지
- 한 캐릭터의 본 수: 8~12개 (부위당 1개 + 무기/장신구)
- 애니메이션 클립 fps: 12~24fps (낮을수록 더 장난감 느낌. 30fps 이상은 너무 부드러워서 복셀과 충돌)

### 폴리곤 예산

- 캐릭터 1유닛: ~500 폴리곤 이하
- 환경 오브제: 100~500 폴리곤
- 200 유닛 시 총 ~10만 폴리곤 (URP GPU Instancing으로 처리 가능)

### 맵 레이아웃

- 전장: 5열 × 14행 (플레이어 5행 + 중립 4행 + 적 5행)
- 3D 환경으로 전장 전체가 항상 존재한다
- 배치/전투 페이즈에 따라 카메라만 이동한다 (맵 자체는 고정)

### 카메라 시스템 (핵심)

카메라는 단순 줌이 아니다. **높이, 각도, DOF가 동시에 변한다.**

| 뷰 레벨 | 카메라 높이 | 카메라 각도 | DOF 강도 | 느낌 | 사용 시점 |
|---------|------------|-----------|---------|------|----------|
| **전체 뷰** | 높음 | 급경사 (60~70°) | 강함 | 디오라마, 토이렌즈 | 배치 단계, 전장 전체 파악 |
| **중간 뷰** | 중간 | 중간 (40~50°) | 보통 | 전략적 관전 | 전투 기본 뷰 |
| **클로즈업** | 낮음 | 거의 수평 (15~25°) | 얕음 (배경 날림) | 드론 촬영, 전장 안에 들어온 느낌 | 전투 중 클로즈업, 역전 순간 |

**DOF 런타임 보간:**
- DOF 파라미터(흐림 강도, 포커스 거리)는 카메라 뷰 레벨에 따라 런타임으로 보간한다
- 카메라 위치/각도 이동과 DOF 값 변경을 하나의 CameraController에서 동시에 처리
- 뷰 레벨별 DOF 프리셋을 ScriptableObject로 관리하고, 전환 시 부드럽게 보간
- URP Volume 파라미터를 코드로 직접 제어 (DOTween으로는 DOF 제어 불가)

**카메라 전환 규칙:**
- 배치 → 전투: 전체 뷰에서 중간 뷰로 자연스럽게 내려옴
- 전투 중: 플레이어가 뷰 레벨 전환 가능 (단축키 또는 마우스 휠)
- 역전/결정적 순간: 자동으로 클로즈업 연출 가능 (옵션)

**Voxel 모델 카메라 워크 규칙 (Low-poly 3D 전환 후):**
- Voxel은 3D 메쉬이므로 카메라 회전/줌에 픽셀 정수 배율 제약 없음
- 자유로운 카메라 워크 가능 (Zoom in/out, 회전, 패닝)
- Mipmap 필터링 OK (멀리서도 깔끔)
- Anti-aliasing: SMAA 권장 (Voxel의 각진 엣지 부드럽게)
- 픽셀 정수 배율 규칙은 더 이상 적용되지 않음 (HD-2D 폐기와 함께)

**카메라가 변하면 느낌이 변한다:**
- 전체 뷰에서는 "장난감 전쟁을 내려다보는" 가벼움
- 클로즈업에서는 "전장 한복판에 들어온" 몰입감
- 같은 전투를 다른 높이에서 보면 다른 게임처럼 느껴져야 한다

### UI 레이어 시스템

게임 내 UI는 **두 종류로 분리**한다:

**1) 게임 UI — 3D 월드 스페이스 (World Space Canvas)**
- 판돈 표시, 라운드 스코어, 페이즈 안내, 손패 정보 등
- 3D 공간의 고정 위치에 배치된다 (페이즈마다 위치 지정)
- 카메라가 이동할 때 UI를 뚫고 지나가거나 스쳐 지나간다
- DOF 영향을 받는다 — 카메라 포커스 밖이면 자연스럽게 흐려진다
- 카메라가 배치→전투로 넘어가면서 배치 UI는 블러되고, 전투 UI가 포커스에 들어옴

**2) 시스템 UI — 2D 스크린 스페이스 (Screen Space Overlay)**
- ESC 메뉴, 설정, 일시정지 등
- 화면에 오버레이로 표시, 카메라 영향 안 받음, 항상 선명

**이 분리가 주는 효과:**
- 카메라 이동 자체가 자연스러운 UI 전환이 된다 (별도 페이드인/아웃 불필요)
- 게임 UI에 DOF가 적용되면서 영화적 느낌이 난다
- 플레이어가 "이 세계 안에 있다"는 몰입감이 강해진다

### 비주얼 원칙 3가지

**원칙 1: 유닛은 항상 읽혀야 한다**
- 담당 필라: 심리전
- 어떤 카메라 뷰에서든 병종이 실루엣만으로 구분 가능해야 한다
- 판단 기준: "전체 뷰에서 축소된 상태로도 기병/궁병/창병이 구분되는가?"

**원칙 2: 대비로 시선을 유도한다**
- 담당 필라: 보는 맛
- 이펙트를 늘리지 말고, 배경을 눌러서 유닛이 돋보이게 한다
- 판단 기준: "화면에서 가장 먼저 눈이 가는 곳이 지금 중요한 곳인가?"

**원칙 3: 결정의 순간은 화면이 반응한다**
- 담당 필라: 보는 맛
- 매치를 좌우하는 결정적 순간 (배치 공개, 극적 충돌, 마지막 라운드, 큰 역전 등) 카메라 줌인, 히트스탑(2~4프레임 정지), 또는 채도 스파이크 중 하나
- 판단 기준: "결정적 순간을 놓치는 플레이어가 있는가? 있다면 연출이 부족한 것"

## 2. Mood & Atmosphere

### 게임 상태별 분위기

| 게임 상태 | 분위기 | 조명 톤 | DOF | 설명 |
|-----------|--------|---------|-----|------|
| **배치 단계** | 긴장, 집중 | 차분한 자연광, 약간 어둡게 | 강함 (토이렌즈) | 전장을 위에서 내려다보며 배치를 고민하는 시간. 조용하고 집중되는 느낌 |
| **공개 순간** | 놀라움, 확인 | 밝아지며 블룸 증가 | 순간적으로 약해짐 (전체 선명) | 양측 배치가 드러나는 0.5~1초. 가장 극적인 시각 전환 |
| **전투 진행** | 몰입, 관전 | 밝고 읽기 쉬운 조명 | 뷰 레벨에 따라 변동 | 병사들이 부딪히는 것을 지켜보는 시간. 깔끔하고 읽기 쉬워야 함 |
| **역전 순간** | 흥분, 반전 | 순간 채도 스파이크 | 클로즈업으로 전환 | 열세 → 우세 전환 시 카메라/연출이 자동 반응 |
| **결과 화면** | 이완, 정산 | 부드러운 자연광 복귀 | 전체 뷰 복귀 | 판돈 정산, 다음 라운드 준비 |

### Tilt-shift가 주는 톤

- **멀리서**: 전장이 귀엽고 장난감 같다. 병사들이 작게 움직이는 게 정겹다
- **가까이서**: 같은 전장이 긴박하고 생생하다. 화살이 날아오고 병사가 넘어진다
- 이 톤의 차이가 DDworld의 고유한 매력이다 — 가볍지만 진지한, 귀엽지만 긴장되는

### 조명 방향

- 기본 광원: 자연광 (태양, 약간 따뜻한 톤)
- 그림자: 있되 부드러운 소프트 섀도우 (하드 섀도우는 픽셀 스프라이트와 충돌)
- 야간/실내 맵은 MVP 범위 밖 — 프로토타입은 주간 야외 전장만

### 환경 디테일 애니메이션

전장 바닥의 잔디, 꽃, 깃발 등 환경 소품은 바람에 흔들리는 애니메이션을 넣는다.
클로즈업 뷰에서 특히 잘 보이며, "살아 있는 전장" 느낌을 준다.

**구현 방식: 셰이더 버텍스 애니메이션**
- 잔디/소품을 3D 평면(quad) 메시로 배치
- URP 셰이더 그래프에서 위쪽 꼭짓점만 사인파로 흔든다 (바람 효과)
- GPU에서 처리되므로 잔디가 수천 개여도 성능 영향 거의 없음
- 개별 스프라이트 오브젝트로 만들지 않는다 (드로콜 폭증 방지)

**뷰 레벨별 효과:**
- 전체 뷰(배치): 잔디가 살랑거리는 게 작게 보임 → 디오라마 생동감
- 클로즈업(전투): 잔디 흔들림이 크게 보이고 DOF로 전경/후경 분리 → 전장 몰입감

## 4. Color System

### 팀 구분: 팔레트 스왑

좌측(플레이어)과 우측(상대)을 색으로 구분한다. 같은 병종이라도 팀 컬러가 다르다.

| 팀 | 기본 컬러 톤 | 용도 |
|----|-------------|------|
| 좌측 (플레이어) | 블루 계열 | 아군 유닛, 아군 UI 강조 |
| 우측 (상대) | 레드 계열 | 적군 유닛, 적군 UI 강조 |

**구현 방식: 셰이더 팔레트 스왑**
- 스프라이트를 그릴 때 팀 컬러 영역(옷, 방패, 깃발 등)을 지정색(마젠타 #FF00FF)으로 칠한다
- URP 커스텀 스프라이트 셰이더가 런타임에 마젠타를 팀 컬러로 교체
- 스프라이트 원본 1장으로 모든 팀/종족 컬러를 지원
- 퍼포먼스 비용 거의 없음 (픽셀당 색 비교 1회)

**종족 확장 대비:**
- MVP: 휴먼 (블루 vs 레드)
- 향후: 종족별 팀 컬러 팔레트 추가 (예: 오크=초록 톤, 네크로맨서=보라 톤)
- 팔레트만 교체하면 같은 스프라이트로 다른 종족 느낌을 낼 수 있음
- 종족별 고유 병종/스프라이트는 별도 에셋으로 제작

### 의미 컬러 (Semantic Colors)

게임 내에서 색이 전달하는 의미를 통일한다.

| 색 | 의미 | 사용 예 |
|----|------|--------|
| 블루 | 아군, 안전 | 아군 유닛, 배치 가능 타일 |
| 레드 | 적군, 위험 | 적군 유닛, 피해 표시 |
| 골드/옐로 | 보상, 가치 | 판돈 표시, 승리 연출 |
| 그린 | 회복, 긍정 | HP 회복 (향후), 긍정 피드백 |
| 그레이 | 비활성, 사용 불가 | 배치 불가 타일, 사용 불가 카드 |

### 환경 팔레트

- HD-2D 스타일답게 환경도 아름답고 디테일하게 표현한다
- 단, **유닛 컬러 영역과 환경 컬러 영역이 겹치지 않아야 한다**
  - 유닛: 블루/레드 톤 → 환경은 블루/레드를 주요 색으로 쓰지 않는다
  - 환경: 자연색 (초록, 갈색, 베이지, 따뜻한 톤) 중심
- 비주얼 원칙 2 적용: "대비로 시선을 유도한다" — 색 분리로 유닛이 자연스럽게 돋보임

### 색맹 대응

- 블루/레드 팀 구분은 적녹색맹에게 안전 (파랑과 빨강은 혼동 적음)
- 추가 안전장치: 팀 구분에 색 외에 실루엣/아이콘 보조 (깃발 방향, 진행 방향 등)
- 색맹 모드는 MVP 범위 밖이나, 팔레트 스왑 구조이므로 나중에 추가 용이
