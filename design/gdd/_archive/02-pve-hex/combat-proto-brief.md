## 구조 규칙 (프로토라도 이건 지켜라 — 검증 방법 자체가 이 위에서 성립)

1. **전투 = 순수 모듈**: `BattleResult Simulate(PlayerPlacement, EnemyFormation, int seed)` 계약. MonoBehaviour Update나 씬에 전투 로직 녹이지 말 것.
2. **SIM ÷ VIEW 분리**: SIM = 헤드리스 데이터 틱(고정 틱, 이동→트리거→공격→사망→상태 순). VIEW = 결과 재생만. 시뮬 안에 DOTween/TMPro/연출 금지.
3. **결정론**: 같은 seed+배치 → 항상 동일 BattleResult. 랜덤 = seed 기반만 (`UnityEngine.Random`·시간 의존 금지).
4. **BattleResult = 분대별 생존/사망 병사 수 출력** — HP이월·permadeath는 지금 적용하지 않되 계약만 갖춰둠 (나중 헥사 연결용).

`typeAdvantage/typeDisadvantage`(상성 배수), `GamePhase`(PvP 흐름), 3판2선승, 덱/핸드 PvP UI.

## 병종 4종 (수치가 아니라 "공격 패턴"으로 구분)

| 병종 | 패턴 |
|------|------|
| 농부 | 부채꼴 근접 물량 + 패닉(분대 50%↓ 시 잠깐 도주 후 복귀) |
| 창병 | 세로 관통(앞열 + 그 뒤 적 동시 타격) |
| 궁병 | 곡사 후열 저격(멈춰 쏘기, 없으면 전진) |
| 기병 | 히트앤런(돌격 보너스→후퇴→재돌격) — **밸브: 구현이 비싸지면 v0는 "돌격 보너스만(후퇴 없음)"으로 강등 허용** |

- 마법사(액티브)·방패병(멀티셀+넉백)·함정 = 제외. 1차는 "배치만으로" 검증.

## 적 3타입 + 혼성 인카운터 3세트 ★

적 = **몬스터** (거울 병종 금지). 타입 3종:
- **돌격 물량 떼**: 직진 다수·약함 (관통·AoE가 꽂힘)
- **후열 저격수**: 뒤에서 쏨·물렁 (기병 다이브·궁병 카운터가 꽂힘)
- **중장 탱커**: 느리고 단단, 앞을 막음 (곡사로 넘기거나 관통으로 뚫어야)

⚠️ **인카운터 = 단일 타입 덩어리 금지, 혼성 진형 프리셋 3개** — 단일 타입은 공간적으로 대칭이라 어디에 놓든 비슷 → "배치가 갈리나" 검증 불가(거짓 음성 위험):
1. **E1 "껍질 깨기"**: 탱커 벽 앞줄 + 저격수 후열 (뚫을까 돌아갈까)
2. **E2 "비대칭 물량"**: 좌측 몰린 돌격 떼 + 우측 빈 레인 (정면 대응 vs 우회)
3. **E3 "혼성"**: 물량 전면 + 탱커 중앙 + 저격수 코너

## 스코프

5x5 그리드(자기 구역), 총 병사 수십 명, 프리미티브 도형(캡슐/큐브). 복셀·400스케일·밸런싱·서든데스·웨이브 전부 제외. 밸런스 값 = 인스펙터 노출.

## 산출물

1. 전투 씬 진입점 1개 (빈 GO + 부트스트랩 스크립트 = 헥사 프로토 패턴): 배치 → 확정 → 자동전투 → 결과.
2. **배치 프리셋 저장/원클릭 재실행** — A/B 비교·결정론 확인의 도구.
3. **결정론 검증**: 같은 seed+배치 2회 → 동일 결과 assert (EditMode 테스트가 간단하면 그걸로, 아니면 시작 시 자동 셀프체크 PASS/FAIL 로그).
4. `Assets/Scripts/Combat/` 아래 새 네임스페이스(`DDworld.CombatProto`)로 격리 — `Systems/`·`Hex/` 안 건드림.
