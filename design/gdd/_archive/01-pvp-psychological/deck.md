# Deck System (덱/카드 시스템)

> **Status**: In Review
> **Author**: nathan (볼트 GDD 이전)
> **Last Updated**: 2026-04-15

## Summary

**런 단위 덱**을 기본으로, **매치 단위 손패 흐름**(3라운드 매치)을 가지는 2계층 시스템.
런 동안 상점/이벤트로 카드 추가/강화가 누적되어 덱이 변화하며, 각 매치 내에서는
드로우/배치/이월의 라운드 흐름이 작동한다. 상대 손패는 매치 단위로 공개되어 심리전의 출발점이 된다.

> **Quick reference** — Layer: `Core` · Priority: `MVP` · Key deps: `Combat`

## Overview

DDworld의 덱 시스템은 **2계층**으로 작동한다:

1. **런 단위 덱 (Run-Level Deck)** — 런 시작 시 기본 덱(45장)으로 시작. 매치 사이 상점/이벤트에서 카드 추가/강화/패시브 획득으로 변화. 빌드 서사의 본질.
2. **매치 단위 손패 (Match-Level Hand)** — 매치 내에서 라운드마다 드로우/배치/이월. 매치 종료 시 덱 상태는 런 단위 덱으로 복귀.

매 라운드 5장을 그리드에 배치하고, 나머지 3장은 다음 라운드로 자동 이월된다.
상대 손패는 매치 시작 시 공개되므로, 어떤 카드를 배치/이월하는지가 심리전의 재료가 된다.

## Player Fantasy

- **전략적 자원 관리** — 지금 배치할 카드와 다음을 위해 아끼는 카드를 고르는 판단
- **읽기의 재료** — 상대가 어떤 카드를 이월했는지 보고 다음 배치를 예측하는 재미
- **역전의 준비** — 이번 라운드를 포기하더라도 다음을 위해 강한 카드를 이월하는 전략

## Detailed Design

### Core Rules

**런 단위 덱 (Run-Level)**:
1. 런 시작 시 플레이어는 기본 덱(45장)으로 시작
2. 매치 사이 상점/이벤트 노드에서 카드 추가, 강화, 패시브 특성 획득 가능
3. 런 동안 덱은 누적 변화하며 빌드 정체성을 형성한다
4. 매치 종료 시 사용된 카드(배치+이월)는 런 덱으로 복귀하여 다음 매치에서 재사용 (셔플 정책: Open Question)

**매치 단위 손패 (Match-Level)**:
5. 매치 시작 시 런 덱에서 카드가 배분된다 (1R: 8장 드로우)
6. 2~3라운드: 이월 3장 + 드로우 5장 = 손패 8장
7. 매 라운드 손패 8장 중 5장을 그리드에 배치한다
8. 배치하지 않은 나머지 3장은 자동으로 다음 라운드에 이월된다
9. 상대의 손패(8장)는 매치 단위로 전체 공개된다 (MVP 확정)
10. 매치는 3판 2선승제 — 최대 3라운드, 2승 달성 시 매치 종료

### States and Transitions

| State | Entry Condition | Exit Condition | Behavior |
|-------|----------------|----------------|----------|
| Run Init | 런 시작 | 런 덱 셋업 완료 | 기본 덱(45장) 로드 또는 이전 런 결과 적용 |
| Run Shop/Event | 매치 사이 노드 진입 | 노드 종료 | 카드 추가/강화/패시브 획득 → 런 덱 갱신 |
| Match Start | PvP 노드 진입 | 1R Draw 완료 | 매치 초기화, 런 덱에서 8장 드로우 |
| Draw | 라운드 시작 | 드로우 완료 | 1R: 8장 / 2R~3R: 이월3 + 드로우5 |
| Hand | 드로우 완료 | 배치 단계 진입 | 손패 8장 확정, 상대에게 공개 |
| Placement | 배치 단계 | 배치 완료 | 5장 선택하여 그리드에 배치 |
| Carryover | 배치 완료 | 라운드 종료 | 배치하지 않은 3장이 자동으로 다음 라운드에 이월 |
| Match End | 2선승 달성 | 카드 복귀 완료 | 사용된 카드 전부 런 덱으로 복귀 (셔플 정책 미정) |

### Card Flow Tables

**매치 내 라운드 흐름 (3판 2선승)**

| 라운드 | 보유 | 드로우 | 손패 합계 | 배치 | 이월 |
|--------|------|--------|-----------|------|------|
| 1R | 0장 | 8장 | 8장 | 5장 | 3장 |
| 2R | 3장 | 5장 | 8장 | 5장 | 3장 |
| 3R (필요시) | 3장 | 5장 | 8장 | 5장 | 3장 |

- 매치 1라운드 최대 카드 소모: 5장 × 3 = 15장 + 이월 풀 3장 = **18장** (45장 덱으로 매치 1개 충분)
- 2:0 스윕 시: 5장 × 2 = 10장 + 이월 3장 = 13장만 사용

**런 흐름 (PvP 매치 중심)**

| 노드 진행 | 덱 변화 | 비고 |
|----------|--------|------|
| 런 시작 | 기본 45장 | 향후 영웅 선택 시 영웅별 시작 덱 (Q7 보류) |
| 매치 1 | 사용 후 덱 복귀 | 매치 결과로 HP 변동, 판돈 적립 |
| 상점/이벤트 | 카드 +N장, 강화, 패시브 | 빌드 서사 형성 |
| 매치 2 | 갱신된 덱으로 진행 | ... |
| ... | ... | ... |
| 마지막 매치 / X승 도달 | 런 종료 | HP 0 도달 시 런 패배 |

### Interactions with Other Systems

| System | Direction | Data Flow |
|--------|-----------|-----------|
| Combat | Deck → Combat | 배치된 5장의 카드 데이터 (병종, 스탯, 강화 상태) 전달 |
| Run Mode | Run Mode ↔ Deck | 매치 사이 덱 갱신 (카드 추가/강화/패시브), 매치 시작/종료 트리거 |
| Shop | Shop → Deck | 카드 추가, 강화, 패시브 특성 부여 |
| Economy | Economy → Deck (간접) | 통화로 상점 구매 → 덱 변화 |

## Formulas

### Draw Count

```
draw_count = (round == 1) ? initial_hand_size : refill_count
```

| Variable | Type | Range | Source | Description |
|----------|------|-------|--------|-------------|
| initial_hand_size | int | 8 | config | 1라운드 초기 드로우 수 |
| refill_count | int | 5 | config | 2라운드 이후 드로우 수 |
| carryover_count | int | 3 | config | 이월 카드 수 |

**Constraint**: `carryover_count + refill_count == initial_hand_size` (항상 손패 8장)

### Deck Composition (런 시작 덱 구성)

양 플레이어는 런 시작 시 동일한 기본 덱(45장)으로 시작한다. 카드는 중복 허용 (같은 병종 여러 장).
런 진행 중 상점/이벤트로 덱이 변화한다.

```
base_deck_size = cavalry + militia + spearman + archer + trap
               = 10 + 10 + 10 + 10 + 5 = 45
```

| 병종 | 장수 | 비율 |
|------|------|------|
| 기병 (Cavalry) | 10장 | 22% |
| 민병대 (Militia) | 10장 | 22% |
| 창병 (Spearman) | 10장 | 22% |
| 궁병 (Archer) | 10장 | 22% |
| 함정 (Trap) | 5장 | 11% |

**매치 단위 소비 검증 (3판 2선승):**
- 매 라운드 배치 5장 + 이월 3장
- 최대 3라운드: 5장 × 3 = 15장 + 이월 풀 3장 = 18장 사용 (덱 잔여 27장)
- 2:0 스윕 시: 10장 + 3장 = 13장 사용
- **결론: 45장이면 매치 1개 충분. 매치 종료 시 카드 복귀로 다음 매치도 가능**

**런 단위 검증:**
- 1런 = 매치 3~5개 + 부가 노드
- 매치마다 카드 복귀 + 상점 추가 → 덱은 점진적으로 커짐 (~50~70장 예상)
- 카드 부족 발생 안 함

**Note**: 향후 영웅 시스템 도입 시 영웅별 시작 덱 차별화 가능 (Q7 보류).

## Edge Cases

| Scenario | Expected Behavior | Rationale |
|----------|------------------|-----------|
| 덱에 드로우할 카드가 부족 | 발생하지 않음 (45장 덱 / 매치당 최대 18장 소모) | Deck Composition 검증 참조 |
| 이월 카드가 3장 미만 (손패 부족) | 발생하지 않음 (매 라운드 항상 8장 보장) | 45장 덱 + 매치당 18장 소모 |
| 1라운드에서 8장 미만 드로우 | 발생하지 않음 (덱 크기 보장) | 덱 풀 설계로 방지 |
| 매치 종료 후 다음 매치 시작 시 덱 상태 | 사용된 카드 모두 런 덱으로 복귀 후 셔플 | 셔플 정책 (Open Question) |
| 상점에서 같은 카드 중복 추가 | 허용 (중복 허용 원칙) | 빌드 정체성 강화 가능 |

## Game Feel

### Feel Reference

포커의 핸드 공개 — 상대 패를 볼 때의 긴장감. 슬레이 더 스파이어의 카드 선택 —
한정된 손패에서 최선을 고르는 판단.

### Weight and Responsiveness Profile

- **Weight**: 가볍고 빠른 카드 조작
- **Snap quality**: 카드 선택/배치가 크리스프하게 반응
- **Player control**: 높음 — 어떤 5장을 배치할지 완전한 통제 (나머지 3장은 자동 이월)

### Feel Acceptance Criteria

- [ ] 카드 드로우 시 각 카드가 구분 가능하게 표시된다
- [ ] 상대 손패 공개가 자연스럽고 읽기 쉽다
- [ ] 배치 후 남은 3장이 자동 이월되는 것이 명확히 전달된다

## Acceptance Criteria

**매치 단위**:
- [ ] 1라운드에 8장이 드로우된다
- [ ] 2~3라운드에 이월 3장 + 드로우 5장 = 손패 8장이 유지된다
- [ ] 손패에서 5장을 선택하여 그리드에 배치할 수 있다
- [ ] 배치 후 나머지 3장이 자동으로 이월된다
- [ ] 상대의 손패 8장이 매치 단위로 공개된다
- [ ] 매치 종료 시 사용된 카드가 런 덱으로 복귀한다

**런 단위**:
- [ ] 런 시작 시 기본 덱(45장)이 로드된다
- [ ] 상점에서 카드 추가 시 런 덱이 갱신된다
- [ ] 상점에서 카드 강화 시 해당 카드의 능력치가 변경된다
- [ ] 다음 매치는 갱신된 런 덱으로 시작된다

**시스템**:
- [ ] 덱 셔플이 결정론적(deterministic)이다 (시드 기반)
- [ ] 카드 수량에 하드코딩 없음 (config 파일로 관리)
