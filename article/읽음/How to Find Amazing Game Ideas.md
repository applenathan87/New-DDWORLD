## 주요 내용

### 1. 게임 아이디어의 4가지 원천

**기존 게임에서 출발:**
- 다른 관점에서 재해석 (Factorio를 1인칭으로 → Satisfactory)
- 테마/배경만 바꾸기 (Minecraft를 수중으로 → Subnautica)
- 매체 변경 (보드게임을 디지털화 → Among Us)
- Brown: "모든 게임은 그 이전의 것들을 기반으로 한다"

**장르 활용:**
- 장르의 문제점을 파악하고 해결 (무작위성 문제를 개선한 Crypt of the NecroDancer)
- 여러 장르 결합 (Spelunky = 플랫포머 + 로그라이크)
- 핵심 메커니즘을 추출해 새 맥락에 적용

**새로운 메커니즘 만들기:**
- 실제 경험에서 영감 (여행 경험 → Papers, Please)
- 컨트롤러 기능 탐색 (GameCube 아날로그 버튼 → Super Mario Sunshine)
- 기존 게임의 특정 메커니즘을 분리·확장

**플레이어 경험에서 출발:**
- 역할극 판타지 (FTL의 우주선 함장)
- 주제 탐구 (Spiritfarer의 죽음에 대한 사색)
- 개인적 경험 (That Dragon, Cancer)

### 2. 하향식 vs 상향식 개발
- 상향식: 메커니즘부터 시작 → 테마를 나중에 입힘
- 하향식: 경험/이야기부터 시작 → 그에 맞는 메커니즘 선택

### 3. 빠른 아이디어 발상 팁 10가지
1. 게임 분해하기 — 메커니즘을 원자 수준으로 분석
2. 비평가 마인드셋 — 장단점 분석 습관
3. 관례에 도전하기 — 기대값을 뒤집어보기
4. 모든 것 플레이하기 — 다양한 장르와 매체 경험
5. 제약 조건 설정하기 — 제한된 범위에서 창의력 발휘
6. 게임 잼 참가 — 테마 기반으로 짧은 시간 내 개발
7. 에디터 열기 — 만드는 과정에서 아이디어 발견
8. 음악과 미술 감상 — 게임 외 예술에서 영감
9. 강제하지 않기 — 산책·휴식 중 자연스럽게 발상
10. 작게 유지하기 — 씨앗처럼 성장시킬 수 있는 개념부터 시작

### 4. 아이디어 평가 기준 3가지

**실제로 만들 수 있는가?**
- 시간, 인원, 예산, 경험 고려
- 게임플레이 프로토타입 제작 소요 시간이 최종 개발 시간 지표

**게임이 돋보일 것인가?**
- 훅(Hook): 사람들이 관심을 갖도록 하는 요소
- 신문 헤드라인 테스트: "흥미로운 기사 제목을 지을 수 있는가?"
- 앵커(Anchor): 친숙한 요소로 이해를 쉽게 만들기
- 혼합 전략: "간단한 기반 + 예상 밖의 요소"

**마케팅이 가능한가?**
- 영상 트레일러로 표현 가능한가? (Lucas Pope 기준)
- Steam 스토어 페이지 자산을 미리 상상해보기

## DDworld에 적용할 수 있는 것
- 아이디어 원천 4가지 중 "플레이어 경험에서 출발"이 DDworld 방향(몰입감·감정 중심)과 가장 일치
- 신문 헤드라인 테스트: DDworld를 한 문장 기사 제목으로 쓸 수 있는지 확인
- 작게 시작: 핵심 메커닉 하나를 씨앗으로 두고 거기서 확장
- "두뇌는 훌륭한 게임 시뮬레이터가 아님" → 프로토타입 제작이 유일한 검증 방법
