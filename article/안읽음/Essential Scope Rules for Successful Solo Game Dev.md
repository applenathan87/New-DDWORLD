# Essential Scope Rules for Successful Solo Game Dev
**출처:** [Wayline](https://www.wayline.io/blog/essential-scope-rules-solo-game-dev)
**분류:** 1인 개발 / 스코프 관리

---

## 핵심 메시지
> 솔로 개발자의 가장 큰 적은 능력 부족이 아니라 "조용한 스코프 크리프(Silent Scope Creep)"다. 야망 자체가 문제가 아니라, 그 야망을 현실적 범위 안에 가두는 프레임워크가 없는 것이 문제다. 마이크로 마일스톤, 우선순위 매트릭스, 빠른 반복/피드백 루프로 스코프를 관리해야 한다.

---

## 주요 내용

### 1. 조용한 스코프 크리프 (Silent Scope Creep)
- 저자는 6개월간 솔로 RPG의 정교한 전투 시스템을 만들었지만, 정작 코어 루프(스토리, 퀘스트, 탐험)가 없어 게임이 출시되지 못한 경험을 공유
- 개별적으로는 작아 보이는 기능 추가들이 점진적으로 쌓여 프로젝트를 압도함
- 명확한 정의 없이는 단순 플랫포머가 어느새 오픈월드 RPG로 변질됨

### 2. 마이크로 마일스톤 접근법 (Micro-Milestone Approach)
- 큰 목표를 매일 달성 가능한 구체적 작업으로 쪼갤 것
- "게임 만들기" 같은 모호한 목표 대신 "오늘 플레이어 이동 구현", "오전에 적 스프라이트 3개 디자인" 같은 구체적 목표 설정
- 완료할 때마다 성취감을 얻고, 동기부여를 유지하며, 진행 상황을 가시적으로 확인 가능

### 3. 우선순위 매트릭스 (Prioritization Matrix)
- MVP에 들어갈 것을 결정하려면 냉정한 우선순위 설정이 필수
- 두 축으로 기능을 평가:
  - **필수성(Necessity):** 핵심 게임플레이에 필수적인가?
  - **노력(Effort):** 구현에 얼마나 걸리는가?
- "높은 필수성 + 낮은 노력" 항목부터 먼저 → 플레이 가능하고 재미있는 게임의 기반
- 비필수 항목은 이후 반복으로 미룰 것

### 4. 반복과 피드백 루프 (Iteration and Feedback Loops)
- "작고 잦은 릴리스가 하나의 거대하고 질질 끄는 출시보다 항상 낫다"
- 가능한 빨리 플레이어 손에 게임을 쥐어주고 피드백을 수집하여 핵심 컨셉을 검증
- 게임 개발 저널(데브로그)을 활용하여 진행 상황과 변경사항, 피드백을 문서화
- 데브로그는 커뮤니티 구축에도 도움 — 솔로 개발자에게 특히 중요

### 5. 스코프 관리 도구와 기법 (Tools and Techniques)
- **버전 관리(Git):** 변경 추적과 실수 되돌리기를 위해 "비협상적 필수(non-negotiable)"
- **작업 관리 보드(Trello/Asana):** 마이크로 마일스톤을 시각적으로 표현
- **주간 자기 리뷰:** 매주 스코프 크리프를 조기에 식별하고 진행 로그를 업데이트
- 일관된 개발 저널로 비전과 실행이 일치하는지 확인

## DDworld에 적용할 수 있는 것
- **우선순위 매트릭스 당장 적용:** DDworld의 기획 아이디어들을 필수성/노력 두 축으로 분류하여, MVP에 넣을 것과 후순위로 미룰 것을 명확히 구분하기
- **마이크로 마일스톤으로 기획 쪼개기:** "GDD 완성" 같은 막연한 목표 대신 "오늘 코어 루프 한 문장 정의", "이번 주 성장 시스템 흐름도 1장" 같은 일 단위 목표 설정
- **코어 루프부터 확정:** 저자의 실패 사례처럼 세부 시스템에 빠지기 전에 DDworld의 핵심 루프(무엇을 하고 → 무엇을 얻고 → 왜 반복하는가)를 먼저 확정할 것
- **데브로그 활용:** 현재 사용 중인 옵시디언 데브로그를 주간 자기 리뷰 용도로도 활용 — 스코프 크리프 조기 감지에 효과적
