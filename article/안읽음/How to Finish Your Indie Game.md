# How to Finish Your Indie Game
**저자:** Karol Gaida
**출처:** [Medium](https://medium.com/@karolgaida/how-to-finish-your-indie-game-8ce19d5238c)
**분류:** 1인 개발 / 프로젝트 완성

---

## 핵심 메시지
> 2년간 5인 팀으로 인디 게임을 개발하며 겪은 실패와 교훈을 정리한 글. 명확한 비전 없이 기능과 도구 개발에 매몰되면 게임을 완성할 수 없으며, 플레이어 중심 사고와 현실적 일정 관리가 핵심이다.

---

## 주요 내용

### 1. 작업 시간을 현실적으로 예측하라
- 2~3일이면 끝날 것 같은 기능이 실제로는 2주까지 걸림
- 모든 방해 요소와 지연 요인(버그, 회의, 컨디션 등)을 고려해야 함
- 단순한 낙관적 추정이 아닌 현실적인 일정 계획이 필요

### 2. 도구가 아닌 게임 콘텐츠에 집중하라
- 저자의 팀은 실제 게임플레이 콘텐츠 대신 도구와 기능 개발에 2년을 소비
- 프리프로덕션 단계를 언제 끝낼지 명확히 정해야 함
- 플레이어는 개발 도구에 관심 없고, 게임 콘텐츠에만 관심 있음
- 도구 개발은 다음 프로젝트에 재사용 가능할 때만 정당화됨

### 3. 플레이어에 집중하라
- 플레이어는 고객이며, 개발자의 취향이 전부가 아님
- 타겟 플레이어를 명확히 정의하고 그들의 니즈에 집중해야 함
- 모두를 만족시키려다 보면 아무도 만족시키지 못함

### 4. 게임 플로우를 다듬어라
- 플레이어의 신뢰는 얻기 어렵지만 잃기는 쉬움
- 한 번의 버그가 전체 경험을 망칠 수 있음
- 게임의 모든 측면을 반복적으로 테스트하고 수정해야 함
- 반복(이터레이션) 횟수가 많을수록 품질이 올라감

### 5. 금전적 동기의 한계를 인식하라
- 인큐베이터 프로그램을 통해 5명이 소액을 나눠 받았으나 생산성 변화 없음
- 소액의 금전 지원은 오히려 동기를 떨어뜨릴 수 있음
- 프로젝트 자체를 즐기는 사람을 찾는 것이 중요하며, 내재적 동기가 더 강력한 원동력

### 6. 프로젝트 리더가 되라
- 모든 프로젝트에는 리더가 필요하며, 이 역할을 주저하지 말아야 함
- 리더의 역할: 팀원의 업무를 명확히 하고, 완성된 기능을 통합해 실제 게임으로 만들고, 팀원을 테스트하며 새 업무를 배정하고, 팀을 독려하는 것
- 팀 관리는 투자이며, 올바르게 하면 향후 프로젝트에도 큰 자산이 됨

## DDworld에 적용할 수 있는 것
- **프리프로덕션 마감 설정**: 기획 공부 단계에도 "언제까지 기획을 마치고 프로토타입으로 넘어갈지" 명확한 데드라인을 정할 것
- **도구/시스템보다 콘텐츠 우선**: 완벽한 시스템 설계에 매몰되지 말고, 플레이어가 실제로 경험할 콘텐츠(스테이지, 이벤트, 보상 등)를 먼저 구체화할 것
- **타겟 플레이어 정의**: "성장 쾌감, 언락, 빌드업을 좋아하는 플레이어"를 더 구체적으로 정의하고, 그들의 기대에 맞추어 기획할 것
- **작업 시간 버퍼**: 기능 구현 일정을 잡을 때 예상 시간의 2~3배를 잡는 습관 들이기
