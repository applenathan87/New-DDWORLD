# 템플릿 레이아웃 파이프라인 가이드 (C 방법 — 제작 단계에서 좌표 명세 뽑기)

> 원칙: **아트와 코드 사이의 계약은 이미지가 아니라 숫자다.**
> 템플릿 이미지 1장에는 반드시 레이아웃 명세(layout.json) 1개가 따라온다.
> 코드는 명세만 읽으므로, 템플릿 교체 = **이미지 + JSON 교체**로 끝난다 (코드 무수정).
> 작성: 2026-07-04 · 적용 사례: 이력서(resume_template.png + resume_template.layout.json)

## 0. 좌표계 규약

- 원점 = 이미지 **좌상단**, y는 아래로 증가, 단위 = **템플릿 PNG 픽셀**
- 게임 캔버스로는 코드가 `배율 = 캔버스폭 ÷ templateW`를 곱해 일괄 환산 (균등 배율 — 그래서 **캔버스 비율은 템플릿 비율과 일치**시켜야 함)
- 필드 종류 2가지:
  - **rect** `{x, y, w, h}` — 글자/이미지가 들어갈 상자 (title, portrait, quote, banner…)
  - **line y** — 점선의 y좌표 (글자가 그 *위에* 앉음: infoRowYs, clueLineYs)

## 1. 제작 도구별 좌표 추출 방법

### 피그마 (권장 — 무료, 좌표 읽기가 가장 편함)
1. 새 파일 → 템플릿 PNG를 캔버스에 드래그 → **프레임으로 감싸기** (프레임 좌상단이 원점이 됨)
2. 각 필드 위치에 **사각형 도형**을 올리고 레이어 이름을 필드명으로 (title, portrait, quote, banner1…)
3. 사각형을 선택하면 우측 패널에 **X, Y, W, H가 그대로 표시** → layout.json에 옮겨 적기
4. 점선류는 얇은 선 도형을 점선 위에 올리고 Y만 기록
- 장점: 나중에 템플릿을 수정해도 이 피그마 파일이 "좌표 원본"으로 남는다 (아트-코드 계약서)

### 포토샵
- 사각형 선택 도구로 필드 영역을 드래그 → **창 > 정보(Info) 패널**에 X/Y/W/H 표시
- 또는 **슬라이스 도구**로 필드마다 슬라이스를 만들고 이름 지정 → 슬라이스 좌표가 곧 명세
- 눈금자 원점이 좌상단인지 확인 (기본값)

### macOS 미리보기 (임시 측정용)
- 영역 드래그 선택 시 크기가 표시됨. 시작점 좌표는 안 보여줘서 정밀 작업엔 부적합 — 급할 때만

### AI 생성 이미지의 경우 (현재 우리 방식)
- 생성 도구는 좌표를 주지 않으므로, **생성 직후 픽셀 분석을 표준 후처리 단계**로 삼는다:
  ```
  python3 prototypes/unity-prototype/tools/measure_template.py
  ```
  (점선 = 어두운 픽셀 가로 밀집 행, 배너 = 보라 픽셀 덩어리, 액자 = 금색 픽셀 bbox로 검출.
  새 템플릿에 맞게 색 임계값·탐색 창을 조정해서 사용. 주석 이미지가 나오므로 검출 결과를 눈으로 확인)
- 검출이 애매한 요소만 피그마/포토샵으로 보완 측정

## 2. 명세 파일 스키마 (이력서 기준 — 새 템플릿이면 필드 추가/삭제)

```json
{
  "templateW": 1054, "templateH": 1492,          // 원본 PNG 크기 (배율 계산용 — 필수)
  "title":    { "x": 0, "y": 150, "w": 1054, "h": 72 },
  "portrait": { "x": 152, "y": 294, "w": 270, "h": 314 },
  "infoRowYs": [342, 412, 488, 565],             // 정보란 점선 4개의 y
  "infoLabelX": 528, "infoValueX": 660, "infoRightX": 930,
  "quote":    { "x": 475, "y": 582, "w": 465, "h": 66 },
  "banner1":  { "x": 132, "y": 680, "w": 204, "h": 49 },
  "banner2":  { "x": 115, "y": 983, "w": 266, "h": 49 },
  "hintX": 356,
  "rowX": 150, "rowW": 760, "rowH": 56,
  "clueLineYs": [798, 858, 942],                 // 이력 상자 점선 3개의 y
  "special":  { "x": 150, "y": 1040, "w": 760, "h": 100 },
  "stmtStartY": 1040, "stmtStep": 108, "stmtRowH": 96
}
```

- 코드 대응: `Models.cs`의 `ResumeLayout` (필드명 = JSON 키. 파일이 없으면 코드 기본값으로 폴백)
- 새 종이(공문/JD, 질문 카드)를 템플릿화할 때도 같은 패턴: `xxx_template.png` + `xxx_template.layout.json` + 대응 레이아웃 클래스

## 3. 에셋 납품 체크리스트 (제작/발주 시)

- [ ] PNG, **투명 배경** (찢어진 가장자리)
- [ ] **무자 버전** — 필드 영역은 비워두기 (글자·초상화는 게임이 얹는다. 배너 안 글자도 비움 — 번역 대비)
- [ ] 비율 = 게임 캔버스와 동일 (다르면 코드에서 캔버스 크기 재계산 필요 — 이력서는 900×1274 = 1054×1492 비율)
- [ ] 필드 상자 안에 장식 요소 넣지 않기 (텍스트와 겹침)
- [ ] 게임용 해상도: 폭 1024px 내외 권장 (목업용 고해상도는 별도 보관)
- [ ] **layout.json 동봉** (또는 납품 직후 measure_template.py로 생성)

## 4. 적용·검증 절차

1. 이미지 → `Assets/StreamingAssets/MawangHR/`, JSON → 같은 폴더 (이름 짝 맞추기)
2. Play → 해당 종이 확인
3. **오버레이 검증** (눈 대신 겹친 이미지로): 게임 스크린샷과 채움본 목업을 반투명 합성해 어긋남 확인
   ```
   python3 -c "from PIL import Image; a=Image.open('스크린샷.png').convert('RGBA'); b=Image.open('목업.png').convert('RGBA').resize(a.size); Image.blend(a,b,0.5).save('overlay.png')"
   ```
4. 어긋난 필드는 **layout.json 숫자만 수정** (코드 금지) → 다시 Play

## 5. 왜 이렇게 하는가 (요약)

- 눈대중 좌표는 템플릿을 바꿀 때마다 다시 눈대중 — 비용이 반복된다
- 명세가 데이터 파일이면: 템플릿 N종(이력서·공문·카드·인사기록 카드…)이 늘어도 코드가 안 늘고,
  아트 수정 → JSON 갱신 → 끝. 로컬라이즈(글자 길이 변화)에도 상자 기준이라 안전
- 프로덕션 재작성 시에도 이 layout.json들은 그대로 승계된다 (프로토에서 유일하게 버리지 않는 산출물이 데이터)
