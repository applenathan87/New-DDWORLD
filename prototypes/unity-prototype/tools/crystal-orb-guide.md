# 마왕성 연락구(수정구) 제작·연출 가이드

> 대상: 스케줄링 통화 장치 "마왕성 연락구 / HR CALL ORB" — 스펙 시트(2026-07-05, 뿔+날개 받침·보라 수정·태그) 기준.
> 원칙: **구슬 속 아이콘 = 빌보드 스프라이트 홀로그램** (3D 조각 아님) + 에셋 갈아끼우기 규약 (파일 교체 = 완성).
> 관련: 던지기 물리 = ThrowableProp/PropPhysics · 통화 로직 = SchedulingFlow · 스프라이트 로드 = UiKit.LoadSprite

---

## 1. 게임 오브젝트 구조 (목표 계층)

```
OrbProp                    ← 물리 루트 (SphereCollider + ThrowableProp — 기존 유지)
 ├ OrbBase (메쉬)          ← 받침: 혼돈석 + 악마 금속 + 뿔·날개 + 태그 (불투명, 픽셀 텍스처)
 ├ CrystalOrb (메쉬)       ← 구슬: 투명 머티리얼 (URP Lit Transparent, 보라 틴트)
 ├ InnerIcon (쿼드)        ← ★ 아이콘 홀로그램 — 항상 카메라를 보고, 항상 수평 유지
 │   └ RingA / RingB (쿼드) ← 통화 중 파동 링 (스케일↑ + 페이드 루프)
 └ InnerLight (포인트)     ← 상태 연동 발광 (촛불 플리커와 같은 문법)
```

핵심 설계 판단 3가지:
1. **아이콘은 스프라이트다** — 픽셀 해골/체크를 3D로 조각하면 원본 픽셀감이 죽는다. 구슬 안 쿼드 1장에 Unlit 발광 머티리얼.
2. **아이콘은 구슬 회전과 독립** — 이 수정구는 던질 수 있고 굴러간다. InnerIcon은 LateUpdate에서 카메라를 향하고 위쪽을 유지 → 구슬이 데굴데굴 굴러도 해골은 똑바로 떠 있다 ("마력 홀로그램" 픽션 + 코미디).
3. **투명 정렬은 공짜로 해결** — 아이콘이 구슬 안에 있으면 구슬 앞면보다 카메라에서 머니까 먼저 그려지고, 유리가 위에 덮여 "유리 너머로 비치는" 룩이 자동으로 난다. 튀면 아이콘 렌더 큐만 구슬보다 낮게 고정.

## 2. 상태 머신 (3종 — 스펙 시트의 "통화 상태 연출")

| 상태 | 아이콘 | 연출 | 진입 트리거 (기존 코드 연결점) |
|------|--------|------|------------------------------|
| **대기** | 해골 | 느린 맥동 (스케일 0.95~1.05, 알파 0.7~1.0, 주기 ~2초) + 라이트 은은한 사인파 | 기본 / 완료 1초 후 복귀 |
| **통화 중** | 해골 + 파동 링 | 링 2장이 교차로 커지며 페이드 (소나 루프, 주기 ~0.9초) + 라이트 밝게 + 말풍선 등장에 펄스 + 스파클(MagicBurst 축소판 재활용) | `SchedulingFlow.DockToOrb()` — 사진이 수정구에 붙는 순간 |
| **완료** | 체크 | 팝 (스케일 1.4→1.0 스프링) + 라이트 한 번 번쩍, **1초 유지 후 대기 복귀** | 말풍선 숨김 시점 (`HideBubbleAfter` 종료) |

- 상태 전환 = **스프라이트 교체 + 트윈 파라미터 변경**뿐 — 연출 추가 비용이 거의 0인 구조를 유지할 것.
- 통화 중 수정구 던지기는 이미 잠금(`OrbProp.enabled = false`) — 상태 머신과 충돌 없음.

## 3. 에셋 제작 명세 (발주/제작 체크리스트)

### 3a. 모델 (받침 + 구슬) — 로우폴리 + 픽셀 텍스처 (책상 가이드와 동일 파이프라인)
- [ ] 폴리 예산: **180~230 tris** (시트 권장 준수)
- [ ] 크기: 게임 기준 **전체 높이 0.20m** 내외 (구슬 지름 ~0.13m — 현 그레이박스 콜라이더 0.18×0.2와 호환)
- [ ] 머티리얼 슬롯 **2개 분리**: ① 받침(불투명) ② 구슬(투명) — 구슬만 투명 처리해야 하므로 필수
- [ ] 텍스처: 64~128px, 시트 팔레트 5종(마력 수정/혼돈석/악마 금속/고서 종이/마력 램프), **Point 필터**
- [ ] "마력 부족 시 흔들어 주세요" 태그: 모델+텍스처에 포함 (별도 인터랙션 없음 — 능담)
- [ ] FBX, 원점 = 바닥 중앙, 트랜스폼 적용 (블렌더 가이드 §6 동일)

### 3b. 아이콘 스프라이트 — 갈아끼우기 규약
투명 PNG, 32~64px, 안티앨리어싱 금지. 파일 경로 규약 (UiKit.LoadSprite로 로드 — 임포트 설정 무관):

```
Assets/StreamingAssets/MawangHR/Orb/
 ├ icon_idle.png    ← 해골 (1장. 플립북 원하면 icon_idle_0.png, _1.png … 순번)
 ├ icon_call.png    ← 통화 중 해골 (대기와 같아도 됨)
 ├ icon_done.png    ← 체크
 └ ring.png         ← 파동 링 (원형 링 1장 — 스케일/페이드는 코드가)
```
- 파일이 없으면 **절차 생성 임시 스프라이트로 폴백** (이력서 템플릿과 같은 규약 — 에셋이 늦어도 게임은 항상 돈다)

## 4. 렌더링 규칙

- 구슬: URP Lit **Transparent**, 알파 ~0.55, 보라 틴트. 양면 불필요 (앞면만)
- 아이콘/링: **Unlit + 밝은 색** (HDR 강도 >1이면 Bloom에 걸림), 렌더 큐 구슬보다 낮게
- **Bloom 후처리 필수 조건 아님, 그러나 절반의 룩** — 시트의 "뿜어지는 빛"은 Bloom 몫. 로드맵 1단계 후처리(Bloom/DOF/비네트) 도입 시 촛불·마법 버스트와 함께 일괄 적용
- InnerLight: 대기 intensity ~0.6 사인파 / 통화 1.2 / 완료 순간 2.0 스파이크. 그림자 끔 (섀도 아틀라스 경고 예방 — 포인트 라이트 그림자는 촛불 하나만)

## 5. 프로토 구현 순서 (에셋 도착 전에 가능)

1. **OrbFx 컴포넌트 신설**: 상태 enum + 빌보드/맥동/링 루프 코루틴. 임시 스프라이트는 절차 생성(원·해골 대충·체크)으로
2. DeskRig의 현 CrystalOrb(구체 프리미티브)에 InnerIcon/RingA·B/InnerLight 자식 추가
3. SchedulingFlow 연결: DockToOrb → `orbFx.SetCalling()`, 말풍선 종료 → `orbFx.SetDone()`
4. 에셋 도착 시: 받침+구슬 메쉬 교체(프리팹) + Orb/ 폴더에 아이콘 PNG 투입 — 코드 무수정

## 6. 검증 체크리스트

- [ ] 굴러갈 때 아이콘이 계속 수평·카메라 정면인가 (뒤집히면 빌보드 버그)
- [ ] 통화 중 상태에서 스케줄링 종료 시 대기로 복귀하는가 (Cleanup 경로)
- [ ] 던져서 마법 소멸/재생성 후 상태가 대기로 초기화되는가
- [ ] Bloom 없이도(현 프로토) 아이콘이 읽히는가 — Unlit 색 자체로 1차 가독 확보
- [ ] 촛불+연락구 두 광원이 켜진 채 그림자 경고가 안 느는가 (InnerLight 그림자 끔 확인)
