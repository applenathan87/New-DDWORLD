**가설**: ① 판단축 반전("착함=결격")이 플레이 3건 안에 "오?"를 만든다 ② 도장 판정이 계속 찍고 싶은 손맛이 된다.

**실행법**: `mawanghr.unity` 씬 열고 **Play** (전부 코드 생성 — 인스펙터 세팅 불필요).
에러 시 Console 내용을 Claude에게 붙여넣기.

**빌드 이력**:
- **S1 (2026-07-04)**: Day 1 서류 심사 루프 — 공문/JD 대조 → 통과/탈락 도장(간이 연출) → 결산(정답·해설 공개) → 승진 판정. 지원자 7건.
- **S1.5 (2026-07-04)**: ⭐ **단서 마킹 시스템** — 이력서 줄/특이사항 클릭 → 빨간 잉크 표시 + 근거 메모. 근거 ≥1 없으면 도장 불가. 결산에서 판단+근거 이중 채점("판단은 맞았지만 단서는 따로 있었다"). + 텍스트 오버플로 수정(오토사이즈).
- **S2 앞당김 (2026-07-04)**: ⭐ **도장 드래그 물성** — 도장을 잡아(기울어짐+딸깍) 서류 위에 내리찍기. 떨어뜨린 자리에 잉크 자국 + 화면 흔들림 + 절차생성 사운드(쾅/사각/스윽, 에셋 없이 코드 생성). 서류 밖에 놓으면 스냅백. 서류 등장 슬라이드 연출. 버튼 클릭 판정은 제거(드래그 온리).
- **S2-3D (2026-07-04)**: ⭐⭐ **3D 데스크 전환** — 그레이박스 책상+촛불 포인트라이트(플리커)+어두운 석실. 서류 = 월드 캔버스(책상 위 실물). 도장 = 3D 오브젝트. 대기/완료 서류 더미가 책상 위에 물리적으로 쌓임. 마킹·근거 채점·결산은 그대로 이식. 카메라 포즈 튜닝값 = DeskRig.cs 상단 상수.
- **S2-3D.1 (2026-07-04)**: ⭐ **pick-up-to-read 전환** — 카메라 다이브 대신 **클릭한 종이가 카메라 앞으로 물리적으로 들려 올라옴** (카메라는 살짝 푸시인만 → 나중에 몬스터가 프레임에 유지됨). 도장은 들린 종이 면 위를 따라다니다 **커서가 가리킨 바로 그 지점**으로 낙하 (잉크 자국과 정확히 일치 — 낙하 목표를 스크린 광선↔종이 면 교차점으로 변경).
- **S2-3D.2 (2026-07-04)**: **함께 들기 + 클릭 내려놓기** — 어느 종이를 집든 이력서(오른쪽 크게)+공문(왼쪽, 안쪽으로 틀어서)이 **한 쌍의 독서 포즈로 같이 올라옴** (교차 대조가 코어라 스왑 왕복 제거). 내려놓기 = 종이의 빈 영역 클릭 / 허공 클릭 / ESC / 버튼. 환경 콜라이더 제거(허공 판정용). 슬롯 튜닝값 = GameFlow.LiftPapers(거리·상하·좌우·yaw).
- **S2a (2026-07-04)**: ⭐ **전화 스케줄링 퍼즐 (Day 1 후반 업무)** — 심사 종료 후: 통과자 사진 카드 5장(단계 독립 세트) **클릭 = 수정구 통화**(제약 공개+코미디) / **끌기 = 캘린더 슬롯 부착**(6슬롯, 비 예보·보름달 제약) / 전원 배치 후 **초록 도장으로 캘린더에 확정**. 위반 배치 허용 → 요약 뒤 "다음날 아침 사건 보고서"에서 대가 공개. 도장 대상 전환(SetTarget), 콘텐츠 = gamedata.json `scheduling` 블록.
- **S2-3D.3 (2026-07-04)**: ⭐ **깃펜 방향 마킹 (V/X)** — 단서에 **좌클릭 = V(합격 신호) / 우클릭 = X(탈락 신호)** (중립 마킹 대체). 근거 채점이 방향까지 요구: 결산에 "방향을 반대로 읽었다 — 여긴 마왕성이다" 반전 오독 판정 추가. 깃펜 3D 오브젝트: 종이 들면 손 위치로 비행, 마킹마다 깃털 트윗치. 좌 이동 슬롯 + 종이 드래그 재배치(빈 부분 잡고 끌기, 드래그 제스처의 클릭 억제). 평가 체크리스트 = 면접 단계(승진 보상)로 결정.
- S2 (예정): 도장 드래그 물성 + 1차 면접 루프(질문 카드)
- S3 (예정): 3일 구조 + 승진·가젯(촛불/돋보기) + Day 3 이중반전

- **S2a++ (2026-07-04)**: ⭐ **진짜 물리 전환** — 던지기가 수제 포물선 → **Rigidbody 물리**로 교체. 바닥·벽·책상에 콜라이더+반발 재질(레이어 2로 분리해 "허공 클릭=내려놓기" 판정 유지) → **튕기고 구른다** (해골·수정구는 구형 콜라이더라 진짜 굴러감). 멈추면(0.7초 정지) 마법 소멸 → 제자리 재생성. 부딪힘 세기 비례 "톡" 사운드. **도장도 던지기 가능** (세게 휘두르면 날아감, 살짝 놓으면 기존 스냅백 — 코어 루프 속도 보존). 날아가는 물건은 다시 잡아챌 수 있음. 공용 루틴 = PropPhysics.cs → 나중에 몬스터 콜라이더만 달면 "면접자에게 맞고 튕김"이 공짜.

## 2. PvE 전투 프로토타입 — `combat_test`

**스크립트 위치**: `Assets/Scripts/CombatTest/` (네임스페이스 `DDworld.CombatTest`)

**구성 방식**: 원본 PvP 프로토(`Systems/`·`UI/`·SampleScene)는 **무수정 보존**하고,
같은 클래스들의 **네임스페이스 사본**에 PvE를 이식했다 (2026-07-02).
카드 드래그 배치, 병사 진형, HP바, 화살, 넉백, 카메라 연출 등 기존 자산 그대로 계승.

**가설**: 공개된 적(몬스터) 진형을 보고 카운터 배치하는 것이 재미있고, 배치 선택이 결과를 가른다.

**실행법**:
1. 빈 씬 생성 (New Scene)
2. 빈 GameObject 생성 → `CombatTestBootstrap` 컴포넌트 부착
3. Play → 카메라·조명·전장·UI 자동 생성 (한글 폰트는 에디터에서 자동 로드; 안 되면 인스펙터에 `MonaS12 SDF` 지정)

**PvE 흐름** (한 판):
1. 인카운터 시작 → **몬스터 진형이 적 구역(J~N열)에 100% 공개** 표시
2. **손패 = 보유 로스터 전체** (기본: 민병3·창병2·궁병2·기병2·함정1 — Bootstrap 인스펙터에서 조절)
3. 적 진형을 보며 내 구역(A~E열)에 카드 드래그 배치 (최대 5, **최소 1**)
4. 배치 확정 → 자동 전투 (기존 전투 시뮬 그대로: 레인 직진→자유 추적, 사거리, 돌격, 넉백)
5. 승리 → 다음 인카운터 / 패배 → 같은 인카운터 재도전 / E3 클리어 → 캠페인 재시작

**카드 = 보유 로스터 (B안, pve-pivot Q5)**: 드로우/소모 없음 — 배치해도 카드가 사라지지 않고
전투 후 로스터로 복귀. 유일한 손실은 나중에 permadeath(분대 전멸 시 카드 소멸)로 얹는다. v0는 손실 없음.

**전장**: 플레이어(A~E) | **중립 그레이존(F~I)** | 적(J~N) × 5행. 배치 중에도 휠 줌 + 우클릭 팬 가능.

**인카운터 (EncounterLibrary.cs — 스탯·진형 튜닝은 이 파일에서)**:

| 프리셋 | 구성 | 의도 |
|--------|------|------|
| E0 — 고블린 무리 | 고블린×3 산개 | 쉬운 초반 적 (Q19 거리별 난이도의 첫 표본) |
| E1 — 껍질 깨기 | 오우거 벽×2 + 해골 궁수×2 후방 + 고블린 | 뚫을까 돌아갈까 |
| E2 — 비대칭 물량 | 늑대×4 위쪽 집중 + 오우거 아래 단독 | 정면 대응 vs 우회 |
| E3 — 혼성 진형 | 늑대×2 + 오우거 중앙 + 해골 궁수×2 코너 | 종합 시험 |

**몬스터** (아군 거울 아님 — 기존 UnitData 필드로만 구성, 런타임 생성):

| 몬스터 | 특징 |
|--------|------|

| 해골 궁수 | 4기·고정·사거리 3.5 (아군 궁병 1.5보다 김) — 접근 전에 갈림 |
| 오우거 | 2기·HP100·느림(move 5) — 벽 |

**원본 대비 바뀐 것** (전부 CombatTest 사본에만 적용):
- RPS 상성 완전 제거 (`typeAdvantage`/`GetTypeMultiplier` 삭제) — 유불리 = 공격 패턴 × 진형
