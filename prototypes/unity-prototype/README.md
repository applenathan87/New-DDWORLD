# DDworld Unity Prototype

> 이 Unity 프로젝트(`prototypes/unity-prototype/`)에는 두 개의 독립 프로토타입이 공존한다.
> 서로 의존 관계 없음. 각 프로토타입은 별도 씬에서 단독 실행.

---

## 1. 헥사 영토 루프 프로토타입

**스크립트 위치**: `Assets/Scripts/Hex/HexGamePrototype.cs` (네임스페이스 `DDworld.HexPrototype`)

**가설**: 헥사 타일 정착/정복 → 건물(농장·금광) → 영토·골드·카드 성장 → 더 확장하고 싶다는 동기가 생긴다.

**실행법**:
1. 빈 씬 생성
2. 빈 GameObject 생성 → `HexGamePrototype` 컴포넌트 부착
3. Play → 카메라·조명·헥사 맵 자동 생성

**상태**: in-progress (최근: 카메라 Nudge, DOF, 3D 두께 타일, 타일 식별 도형)

## 2. PvE 전투 프로토타입 — `combat_test`

**스크립트 위치**: `Assets/Scripts/CombatTest/` (네임스페이스 `DDworld.CombatTest`)

**구성 방식**: 원본 PvP 프로토(`Systems/`·`UI/`·SampleScene)는 **무수정 보존**하고,
같은 클래스들의 **네임스페이스 사본**에 PvE를 이식했다 (2026-07-02).
카드 드래그 배치, 병사 진형, HP바, 화살, 넉백, 카메라 연출 등 기존 자산 그대로 계승.

**가설**: 공개된 적(몬스터) 진형을 보고 카운터 배치하는 것이 재미있고, 배치 선택이 결과를 가른다.

**실행법**:
1. 빈 씬 생성 (New Scene)
2. 빈 GameObject 생성 → `CombatTestBootstrap` 컴포넌트 부착
3. Play → 카메라·조명·전장·UI 자동 생성 (한글 폰트는 에디터에서 자동 로드; 안 되면 인스펙터에 `MonaS12 SDF` 지정)

**PvE 흐름** (한 판):
1. 인카운터 시작 → **몬스터 진형이 적 구역(J~N열)에 100% 공개** 표시
2. **손패 = 보유 로스터 전체** (기본: 민병3·창병2·궁병2·기병2·함정1 — Bootstrap 인스펙터에서 조절)
3. 적 진형을 보며 내 구역(A~E열)에 카드 드래그 배치 (최대 5, **최소 1**)
4. 배치 확정 → 자동 전투 (기존 전투 시뮬 그대로: 레인 직진→자유 추적, 사거리, 돌격, 넉백)
5. 승리 → 다음 인카운터 / 패배 → 같은 인카운터 재도전 / E3 클리어 → 캠페인 재시작

**카드 = 보유 로스터 (B안, pve-pivot Q5)**: 드로우/소모 없음 — 배치해도 카드가 사라지지 않고
전투 후 로스터로 복귀. 유일한 손실은 나중에 permadeath(분대 전멸 시 카드 소멸)로 얹는다. v0는 손실 없음.

**전장**: 플레이어(A~E) | **중립 그레이존(F~I)** | 적(J~N) × 5행. 배치 중에도 휠 줌 + 우클릭 팬 가능.

**인카운터 (EncounterLibrary.cs — 스탯·진형 튜닝은 이 파일에서)**:

| 프리셋 | 구성 | 의도 |
|--------|------|------|
| E0 — 고블린 무리 | 고블린×3 산개 | 쉬운 초반 적 (Q19 거리별 난이도의 첫 표본) |
| E1 — 껍질 깨기 | 오우거 벽×2 + 해골 궁수×2 후방 + 고블린 | 뚫을까 돌아갈까 |
| E2 — 비대칭 물량 | 늑대×4 위쪽 집중 + 오우거 아래 단독 | 정면 대응 vs 우회 |
| E3 — 혼성 진형 | 늑대×2 + 오우거 중앙 + 해골 궁수×2 코너 | 종합 시험 |

**몬스터** (아군 거울 아님 — 기존 UnitData 필드로만 구성, 런타임 생성):

| 몬스터 | 특징 |
|--------|------|
| 고블린 | 12마리·HP5·약공 — 물량이지만 무름 |
| 늑대 떼 | 8마리·빠름(move 1) — 돌격 러시 |
| 해골 궁수 | 4기·고정·사거리 3.5 (아군 궁병 1.5보다 김) — 접근 전에 갈림 |
| 오우거 | 2기·HP100·느림(move 5) — 벽 |

**원본 대비 바뀐 것** (전부 CombatTest 사본에만 적용):
- RPS 상성 완전 제거 (`typeAdvantage`/`GetTypeMultiplier` 삭제) — 유불리 = 공격 패턴 × 진형
- 적 덱/드로우/랜덤배치 제거 → `EncounterLibrary` 몬스터 진형 **배치 전 선공개**
- 3판 2선승 제거 → 인카운터 진행 (승리 시 다음, 패배 시 재도전)
- 카드 드로우/소모 → **보유 로스터 전량 입장** (`Roster`가 원본 `Deck` 대체)
- 배치 페이즈 카메라: 내 진영 줌인 → **전체 필드 뷰** + 줌/팬 허용 (적을 보며 배치)
- 동시 전멸 = 플레이어 승 (combat.md PvE 관대 처리)
- 배치 최소 1부대 (5장 강제 해제 — Q5 자유 편성)
- 몬스터 커스텀 색 (EncounterLibrary 색 레지스트리 — 원본 UnitData 무수정)
- 유닛 데이터는 전부 런타임 생성 → 씬/에셋 세팅 불필요 (빈 씬 + Bootstrap 하나)

**유지된 규칙** (기존 구현 그대로): 속도 기반 이동+가속, 레인 직진 → 경계/교전 후 자유 추적,
사거리(원거리 멈춰쏘기), 기병 최고속 돌격 보너스, 창병 돌격 방어 반사, 함정 폭발, 넉백, 병사 개별 HP.

**상태**: in-progress (2026-07-02 PvE 이식)

**발견**: (플레이 후 기록 예정)

## 공통 주의사항

- 프로토타입 간 서로 `using`·참조하지 않는다.
- 프로토타입 코드는 `src/` 프로덕션 코드로 직접 진입 금지. 개념 검증 후 처음부터 재작성.
- 프로덕션 시 결정론·SIM/VIEW 분리 필요 (ADR-003) — 이 프로토는 검증용이라 적용하지 않음.
